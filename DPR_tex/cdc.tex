\subsection{Problématique}

Face à la complexité visuelle des pathologies pulmonaires et à la pénurie mondiale de radiologues experts, le projet vise à concevoir un système automatisé basé sur le \textit{Deep Learning} capable de :

\begin{itemize}[leftmargin=1.5em, itemsep=4pt]
  \item \textbf{Détecter} la pneumonie avec une précision clinique élevée ;
  \item \textbf{Fournir} une justification visuelle explicable via Grad-CAM ;
  \item \textbf{Garantir} une intégration sécurisée et fiable dans le flux de travail médical.
\end{itemize}

\subsection{Objectifs}

\begin{enumerate}[leftmargin=1.5em, itemsep=3pt]
  \item Développer une architecture hybride CNN + Swin Transformer pour capturer simultanément les motifs locaux et les relations spatiales globales.
  \item Implémenter un mécanisme de \textbf{fusion guidée} (gated fusion) qui adapte dynamiquement la contribution de chaque branche.
  \item Intégrer un module d'\textbf{explicabilité} (Grad-CAM) pour produire des heatmaps justifiant la décision.
  \item Évaluer rigoureusement le système sur des métriques cliniques reconnues.
\end{enumerate}

\section{Spécifications Techniques}

\subsection{Architecture logicielle}

L'architecture de \textbf{MedFusionNet} repose sur un pipeline en \textbf{6 étapes} :

\begin{enumerate}[leftmargin=1.5em, itemsep=2pt]
  \item \textbf{Entrée} — Image brute $X \in \mathbb{R}^{H \times W}$.
  \item \textbf{Prétraitement} — Normalisation et redimensionnement : $\tilde{X} = T(X)$.
  \item \textbf{Branche CNN} — Extraction de caractéristiques locales : $F_c = \Phi_c(\tilde{X})$.
  \item \textbf{Branche Swin Transformer} — Extraction de caractéristiques globales : $F_s = \Phi_s(\tilde{X})$.
  \item \textbf{Fusion guidée} — Combinaison adaptative : $F = g \odot F_c + (1-g) \odot F_s$.
  \item \textbf{Classification} — Score, probabilité et Grad-CAM : $\hat{y}, p(y|X)$.
\end{enumerate}

\subsection{Contraintes techniques}

\begin{itemize}[leftmargin=1.5em, itemsep=4pt]
  \item \textbf{Ressources GPU limitées} : l'entraînement doit être compatible avec les quotas Google Colab / Kaggle.
  \item \textbf{Taille des images} : redimensionnement à $384 \times 384$ pour équilibrer qualité et coût mémoire.
  \item \textbf{Données médicales} : utilisation exclusive de datasets publics (pas de données privées de patients).
  \item \textbf{Reproductibilité} : fixation des seeds aléatoires et documentation complète des hyperparamètres.
\end{itemize}

\subsection{Métriques de performance}

\renewcommand{\arraystretch}{1.4}
\begin{tabularx}{\linewidth}{@{}l X c@{}}
  \toprule
  \textbf{Métrique} & \textbf{Description} & \textbf{Seuil visé} \\
  \midrule
  Accuracy & Pourcentage de prédictions correctes sur l'ensemble de test & $\geq 92\%$ \\
  \rowcolor{grisClair}
  Precision & Proportion de vrais positifs parmi les prédictions positives & $\geq 90\%$ \\

  ECE & Expected Calibration Error — qualité de la calibration & $\leq 0.05$ \\
  \bottomrule
\end{tabularx}

\subsection{Critères de recette}

Le projet est considéré comme validé si :

\begin{enumerate}[leftmargin=1.5em, itemsep=4pt]
  \item Le modèle atteint les seuils de performance définis ci-dessus sur le jeu de test.
  \item Les heatmaps Grad-CAM sont générées et cohérentes visuellement avec les zones pathologiques.
  \item Le code est documenté, reproductible et versionné sur GitHub.
  \item Le rapport et la présentation Beamer sont complets et validés par l'encadrant(e).
  \item Le chemin critique du planning est respecté avec un écart maximal de 5 jours.
